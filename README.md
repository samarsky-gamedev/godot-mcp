# MCP сервер для игрового движка Godot

Учебный прототип. MCP интеграция общего назначения
для Godot и ИИ клиентов Codex / Claude Code. 14 инструментов от Coding-Solo
и 2 собственных дополнения. Это минимальная версия, не коммерческий релиз.

## Быстрый старт

Нужны Node.js 18+ с npm и редактор Godot 4. На этой машине проверен Godot 4.7.1.
Откройте терминал в папке prototype и выполните:

```powershell
npm ci --ignore-scripts
npm run build
$env:GODOT_PATH = 'C:\path\to\Godot_console.exe'
npm test
node scripts/demo.mjs demo-second
```

Последняя команда требует новую несуществующую выходную папку. Она создаёт
project.godot, затем через настоящий MCP сервер создаёт main.tscn, добавляет
Label, читает дерево и проверяет запуск. Выводится путь к результату.
Уже готовый пример находится в demo-defense; main.tscn можно открыть в Godot.
Это демонстрация работы инструментов, а не самостоятельно придуманная агентом игра.

## Подключение Codex

В examples/codex.config.toml замените пути к Node.js, build/index.js и Godot.
Добавьте раздел в конфигурацию выбранного доверенного проекта или пользователя,
не заменяя другие настройки. После обновления конфигурации перезапустите сессию.
Сервер называется godot_lab, поэтому не подменяет существующий сервер godot.

## Подключение Claude Code

В examples/claude.mcp.json замените те же пути. Содержимое mcpServers можно
объединить с .mcp.json выбранного демонстрационного проекта. При запуске клиента
просмотрите запрос доверия к проектному серверу. Проверьте подключение через /mcp.
Автоматическая запись конфигурации и изменение разрешений пользователя не выполнялись.

## Задание для демонстрации в агенте

«Используй godot_lab. Получи версию Godot. В моём отдельном тестовом проекте
создай сцену demo.tscn с корнем Node2D, добавь Label с текстом Hello MCP.
Покажи сохранённое дерево через godot_inspect_scene. Запусти
godot_validate_project, объясни статус импорта и запуска. Не изменяй другие проекты».

Основную сцену проекта следует назначить перед validate_project; в готовом
скрипте демонстрации это уже сделано. Не выдавайте эту техническую сцену за игру.

## Новые инструменты

- godot_inspect_scene(projectPath, scenePath): абсолютная папка доверенного
  проекта и путь res://...tscn. Возвращает сохранённые имена, типы и пути узлов.
  Используется SceneState, узлы не инстанцируются. Не отображает живое дерево.
- godot_validate_project(projectPath, frames=60): импорт до 60 секунд, затем
  headless запуск на 1–600 кадров с таймаутом 30 секунд. Возвращает stdout,
  stderr, коды выхода и итог по стадиям. Ошибка GDScript означает isError=true.

## Проверка

`npm test` выполняет интеграционный тест через официальный MCP SDK клиент и
настоящий Godot: handshake, tools/list, создание сцены и узла, инспекция,
успешная проверка, неверные аргументы, сломанный GDScript. Результат:
evidence/acceptance.json. demo-defense/mcp-trace.json содержит отдельный прогон.
Тест проверен 6 ноября 2026 года. Он не покрывает все инструменты исходной базы.
Фактические сессии Codex и Claude Code ещё не проходили интерактивную приёмку.

## Ограничения

Сервер исполняет доверенные проекты с правами пользователя, не является песочницей.
Нельзя запускать непроверенные проекты как способ их безопасно изучить.
Новый инструмент ограничивает путь инспекции проектом, но это не общая защита
унаследованных инструментов. Проверка на несколько кадров не доказывает качество
геймплея, графики, сети или отсутствие всех ошибок. Платежей и подписок нет.
Перед публичной поставкой нужны аудит базы и зависимостей, обновление SDK,
тестирование установки и совместимости. Исходная игра не требуется и не изменена.
